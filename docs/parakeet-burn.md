# Parakeet Burn port — bring-up status

Native int8 Parakeet-TDT-0.6B-v3 without ONNX Runtime (`src/parakeet_burn/mod.rs:1`).
`parakeet-rs` (ORT) stays the default engine; this port is selected per run and
fails fast until it can transcribe end to end, so a half-wired model can never
silently mistranscribe.

## Selection

* Runtime flag: `--parakeet-engine ort|burn` (`STTD_PARAKEET_ENGINE`, `src/cli.rs:186`), default `ort`. Only meaningful with a Parakeet `--model`; other engines ignore it. Non-Parakeet `--model` + `burn` warns and has no effect (`src/main.rs:1377`).
* Build gate: `burn` needs `--features parakeet-burn`; `burn` + `--gpu` additionally needs `--features parakeet-burn-cuda` (`src/cli.rs:186-189`, `Cargo.toml:68-79`). Without the feature, `burn` bails with the rebuild command (`src/asr.rs:122-128`).
* Dispatch: `asr::load_model` (`src/asr.rs:114-131`) routes Parakeet `ModelRef` to `ParakeetBurnModel::load` or the ORT path. Everything engine-agnostic (worker loop, gates, metrics, conditioning) is shared.
* CUDA note: `burn-cuda` 0.21 (cudarc 0.19.9) rejects the CUDA 13.4 toolkit on this host (`Cargo.toml:73-77`); CPU Burn is unaffected, GPU bring-up waits on a cudarc release with CUDA 13.x support.

## Converted weights

`burn-import` cannot ingest the quantized graph (`DynamicQuantizeLinear`, `MatMulInteger`, `ConvInteger`, `DynamicQuantizeLSTM`), so the converter extracts static int8 weights + scales into safetensors (`src/parakeet_burn/weights.rs:1-11`):

```
python3 tools/convert-parakeet-int8-to-burn.py --model-dir models/parakeet-tdt-0.6b-v3-int8
python3 tools/convert-parakeet-int8-to-burn.py --model-dir models/parakeet-tdt-0.6b-v3-int8 --check-only  # inspect, don't write
```

Outputs next to the ONNX files: `encoder-burn.safetensors` + `decoder_joint-burn.safetensors` + `encoder-manifest.json` (existing `vocab.txt` is reused). Converter keeps `<base>` (U8/I8) + `<base>.scale`/`<base>.zero_point` pairs, plain F32 biases, the frozen relative-position table (`pos_enc.table`, `(9999, 1024)` from the encoder `Constant`), and the per-layer depthwise-bias map (`dw_bias`, traced through `Reshape` to the anonymous `onnx::Conv_*` initializer). `load` refuses to start without the two safetensors and prints the exact command (`src/parakeet_burn/weights.rs:22-44`).

## Tests

* Unit (no weights): `cargo test --features parakeet-burn` — 264 pass (frontend incl. parallel determinism, greedy, quant (probe-pinned `dynamic_quantize_u8`, per-tensor batching, transpose, row-direct quantize + tiled-GEMM exactness over T32 shapes), vocab (`{token} {id}` parsing), backend matmul, manifest validation (incl. conv groups), layernorm (biased, f64 accumulators)/Swish/GLU/attention (direction-pinned synthetic)/pos-window, conv stride/pad geometry (+exact parallel/depthwise/1x1 twins), depthwise routing, exact staged length, full-stack `encoder_want` coverage, joint fixed names, embed lookup (+OOB panic), LSTM zero-step + `iofc` gate order.
* Real weights (ignored): `cargo test --release --features parakeet-burn -- --ignored` — 11 pass (needs `encoder-burn.safetensors` + `encoder-manifest.json` on disk). Covers layer-0 `block_forward` finiteness + norm invariant, pre-encode shape/finiteness/determinism, full-`BurnEncoder` load + forward shape/finiteness/determinism, five ORT golden parity tests, the fused-LSTM joint step test, and `profile_breakdown` (release-only per-stage timings + e2e token tripwire).
* ORT parity goldens (`src/parakeet_burn/testdata/`): `pre_encode_golden.safetensors` (T=64 seed-1234 mel → `/pre_encode/out/Add_output_0`, bound 0.1%), `layer0_golden.safetensors` (that output → `/layers.0/norm_out/...`, bound 0.1%), `layer0_stages.safetensors` (same run → `/layers.0/Add*` + pre-softmax `Div` + pre-shift AC/BD terms; branch bounds 0.01, scores 0.001), `encoder_full_golden.safetensors` (same mel → every `/layers.N/norm_out` + final `outputs`; isolated bounds 2%, 0.02 absolute for the tiny final layer), `joint_golden.safetensors` (blank-in, chained blank-in, non-blank-in steps with logits + states; bounds 1% logits, 10% states) — all from onnxruntime-CPU runs. Residuals are f32 rounding only (1-op probe: 1.5e-6); the layer-0 golden also pins the MatMul transpose. fp32-vs-int8 residual is activation-requantization noise — cross-checked against an independent numpy fp32 replication agreeing to 3 decimals (bias 0.10): pre-encode max 85.6 at ref_max 3921 (bound 5%), layer-0 max 0.85 at ref_max 75.8 (bound 3%). Isolated per-block parity (each block on ORT's exact input for its depth) is flat at ~2-15% relative (bounds 20%, 0.02 absolute for the tiny final layer with ref_max ~0.12) — no depth spikes, so no mis-mapped layer. Chained full-depth drift (max 0.05 at ref_max 0.12) is reported, not asserted: per-block noise amplifies down the residual stack and only exact `DynamicQuantizeLinear` replication (step 4) removes it. The layer-0 golden pins the MatMul transpose: without it every Conformer linear silently transposes.
